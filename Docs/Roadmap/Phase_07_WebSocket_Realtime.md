# Phase 07 — WebSocket Real-time Layer

## 1. Module Planning: WebSocket Real-time Layer

### 1.1 Purpose
The purpose of this phase is to establish the real-time communication tier. This maps Spring Boot WebSockets with the STOMP protocol, secures connection Handshakes with JWTs, and streams model execution events (`TURN_STARTED`, `CONTENT_CHUNK` streaming, `TURN_COMPLETED`) to clients.

### 1.2 Package / Folder Structure
```
backend/src/main/java/com/conclave/
├── config/
│   └── WebSocketConfig.java            # Configures STOMP broker endpoints
├── controller/
│   └── ChatController.java             # Exposes POST /api/chat/message
├── security/
│   └── WebSocketAuthChannelInterceptor.java  # Validates JWT on socket CONNECT
└── dto/ws/
    ├── WsEvent.java                    # Base payload wrapper
    ├── TurnStartedEvent.java           # Fires when a model begins thinking
    ├── ContentChunkEvent.java          # Sends message text increments (deltas)
    ├── TurnCompletedEvent.java         # Sends final summary and usage logs
    └── SystemInterventionEvent.java    # (Declared here, used in Phase 08)
```

### 1.3 Responsibilities & Dependencies
- **STOMP Broker:** Bootstraps broker `/topic`. Exposes connection handshake endpoint at `/ws-conclave` with CORS mapping matching the frontend origin.
- **Async Streaming Execution:** Modifies standard HTTP blocking turns. `POST /api/chat/message` returns `202 Accepted` immediately. The model turn executes asynchronously (utilizing Java 21 Virtual Threads via a task executor), broadcasting content chunks through `SimpMessagingTemplate` as they are generated by the model.
- **WebSocket Auth Channel Interceptor:** Intercepts incoming messages. On `CONNECT` command frames, reads the custom `Authorization` STOMP header, validates the JWT, and binds the principal to the WebSocket session.

## 2. Module Components

### 2.1 Mapped STOMP Events (JSON Payloads)

#### 1. `TURN_STARTED` (Broadcaster event)
- Triggered before invoking `ChatClient`.
- Payload: `{ type: "TURN_STARTED", roleName: "Code-Critic", modelId: "MISTRAL", isMocked: false }`

#### 2. `CONTENT_CHUNK` (Broadcaster event)
- Triggered for each text delta.
- Payload: `{ type: "CONTENT_CHUNK", delta: "String", messageId: "UUID" }`

#### 3. `TURN_COMPLETED` (Broadcaster event)
- Triggered after saving message and completing token audits.
- Payload: `{ type: "TURN_COMPLETED", messageId: "UUID", summary: "String", usage: { promptTokens, completionTokens } }`

## 3. Atomic Implementation Tasks

### Task 7.1: Configure WebSocket STOMP Broker
- **Estimated Size:** M
- **Risk:** Medium
- **Prerequisites:** Phase 02 Domain Models
- **Definition of Done:**
  - `WebSocketConfig.java` created implementing `WebSocketMessageBrokerConfigurer`.
  - Registers endpoint `/ws-conclave` and enables simple broker destination `/topic`.
  - Enables CORS mapping to permit frontend origin.
  - Setup simple test client (using node-stomp or JUnit websocket testing library) verifying connection handshake succeeds.

### Task 7.2: Create WebSocket Security Channel Interceptor
- **Estimated Size:** M
- **Risk:** High
- **Prerequisites:** Task 7.1 & Phase 02 JWT Services
- **Definition of Done:**
  - Create `WebSocketAuthChannelInterceptor.java` extending `ChannelInterceptor`.
  - Override `preSend` to inspect `StompHeaderAccessor`.
  - Extract Bearer token from headers when command is `CONNECT`.
  - Validate JWT via `JwtService` and set User principal on the accessor.
  - Configure interceptor inside `WebSocketConfig`.
  - Integration tests verify socket connection fails with invalid or missing tokens.

### Task 7.3: Implement Chat Controller and Async Message Orchestration
- **Estimated Size:** L
- **Risk:** High
- **Prerequisites:** Task 7.2 & Phase 06 Orchestration
- **Definition of Done:**
  - Create DTO `ChatMessageRequest.java` `{ roomId, content, isIntervention }`.
  - Create `ChatController.java` with REST mapping `POST /api/chat/message`.
  - Inject custom `TaskExecutor` (configured to use Virtual Threads: `Executors.newVirtualThreadPerTaskExecutor()`).
  - Upon receiving message, validate request, save user message to history, and trigger async thread pool task to process the AI turn.
  - Return `202 Accepted` response.
  - Async task stream handler:
    - Publish `TURN_STARTED` event via `SimpMessagingTemplate` to `/topic/room/{roomId}`.
    - Call resolved `ChatClient.stream()` model method.
    - On client stream delta event: Publish `CONTENT_CHUNK` containing string updates.
    - On complete: Persist model response, log usage metrics, and broadcast `TURN_COMPLETED`.
  - Integration tests assert complete WebSocket transmission stream matches specification payload layouts.
