# Learning 06: WebSocket Real-time Streaming with STOMP

## 1. Problem Statement
HTTP polling to get real-time token chunks generated by AI models is inefficient, generating massive server request overhead and high latency. Users need to see model completions streaming in word-by-word (or token-by-token) dynamically to create a premium chat workspace experience.

## 2. Decision Rationale
We chose **WebSocket STOMP (Simple Text Oriented Messaging Protocol)**:
- Reduces transport overhead by establishing a single TCP connection.
- STOMP provides clean, structured pub/sub destination routing endpoints (e.g. `/topic/room/{roomId}`).
- Enables easy server-to-client streaming push events, including chunk tokens, turn metadata, and pause signals.

## 3. Alternatives Considered
- **Server-Sent Events (SSE):** Rejected because SSE is unidirectional. Sockets require bidirectional real-time channels to handle interactive client-side pause, resume, and intervention overrides.
- **Raw WebSockets:** Rejected because raw sockets require manual JSON parsing, subscription path routing protocols, and custom connection multiplexing.

## 4. Internal Working
1.  **Handshake Security:** The client initiates connection to `/ws-conclave`. An interceptor validates the JWT from connect headers and binds the user profile.
2.  **Streaming Chunks:** During generation, the backend adapter captures chunks and publishes them to `/topic/room/{roomId}` destination.
3.  **Client Sync:** The web browser receives the STOMP message, parses the payload type, and dispatches the data to Zustand stores.

## 7. Common Pitfalls
- **Missing Token Header:** STOMP libraries do not automatically forward HTTP cookies or auth headers on handshake. The client must pass the JWT explicitly in the connect headers.
- **Heartbeat Timeout:** Sockets close under inactivity. Custom incoming/outgoing heartbeats (e.g. 4000ms) prevent network switches from dropping idle socket connections.

## 8. Debugging Tips
- Monitor the developer console or Network tab for incoming STOMP frames (CONNECT, SUBSCRIBE, SEND).
- Trace interceptor processing by checking debug logs inside `WebSocketAuthChannelInterceptor.preSend`.
