# Conclave — Multi-Provider AI Consensus Workspace

Conclave is a collaborative engineering workspace where multiple LLM models (Google Gemini, OpenAI GPT, Anthropic Claude) collaborate, debate, and refine plans in a live, real-time environment. 

---

## 🎯 System Overview & Rationale

### What problem does this solve?
When building complex prompts or drafting documentation using LLMs, single-model completions suffer from individual biases, blind spots, and stylistic limitations. Unifying multiple LLMs inside a single "Consensus Workspace" allows:
- **Sequential Multi-Agent Workflows:** A text generator (e.g. GPT-4o) drafts content, a critic (e.g. Claude 3.5 Sonnet) audits it, and a third agent merges corrections.
- **Cross-Model Validation:** Prompts are evaluated by different model architectures simultaneously, finding logical discrepancies.
- **Unified Conversation History:** By storing conversations in a **Canonical Message Model**, any model can be re-prompted using contexts generated by its competitors without vendor lock-in.

## 🛠️ Technology Stack Showcase

| Layer | Technology Choice | Architectural Justification |
| :--- | :--- | :--- |
| **Backend** | Spring Boot 3.3 / Java 21 | Leverages Java 21 Virtual Threads to handle concurrent, blocking LLM API calls without thread pool exhaustion. |
| **Database** | PostgreSQL 16 | Relational consistency. Utilizes **Pessimistic Write Locks** (`select ... for update`) to prevent race conditions during pipeline pauses. |
| **Real-time** | WebSockets (STOMP Protocol) | Provides structured, bidirectional pub/sub message routing for streaming AI tokens chunk-by-chunk. |
| **Frontend** | React 19 / Vite / Tailwind CSS | Fast hot-module reloading. Uses custom Level 0 - Level 3 dark elevation panels with Inter and monospaced typography. |
| **State** | Zustand | Lightweight state stores. Decouples WebSocket client stream callbacks from React re-render lifecycles. |
| **Testing** | JUnit / Vitest / Playwright | End-to-end coverage spanning Java controller unit tests, React component tests, and browser E2E flows. |

## 🏁 Quickstart Guide

### 1. Database Provisioning
Launch the PostgreSQL 16 database using Docker Compose:
```bash
docker compose up -d
```

### 2. Backend Bootstrapping
1. Navigate to the `backend/` directory.
2. Setup environment credentials:
   - Copy `.env.example` in the root folder to `.env` and fill out your GCP Project ID and Location.
3. Run compilation and start the application:
   ```bash
   mvn clean install
   mvn spring-boot:run
   ```
   The backend server listens on `http://localhost:8080`.

### 3. Frontend Execution
1. Navigate to the `frontend/` directory.
2. Install dependencies and start the Vite development server:
   ```bash
   npm install
   npm run dev
   ```
   Open your browser to `http://localhost:5173`.
